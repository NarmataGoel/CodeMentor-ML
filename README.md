# 🧠 CodeMentor ML

### An ML-powered DSA learning assistant that learns from how you practice.

CodeMentor ML is a personalized **Data Structures & Algorithms learning platform** that combines a React-based coding tracker with a machine learning backend.

Instead of treating every learner the same, CodeMentor analyzes a student's previous practice behavior to answer questions like:

- **How likely am I to solve this problem successfully?**
- **Which DSA topics are actually weak for me?**
- **Am I repeatedly struggling with the same type of problem?**
- **What should I practice next?**

The goal is simple:

> **Turn coding practice history into personalized learning decisions.**

---

## ✨ Why CodeMentor?

Most coding trackers answer:

> "How many problems did I solve?"

CodeMentor tries to answer something more useful:

> **"What should I solve next, and why?"**

A student's practice history contains useful signals — previous attempts, success rate, recent performance, problem-specific experience, and learning progression.

CodeMentor uses these signals to build a student profile and provide personalized feedback.

---

## 🚀 Key Features

### 🎯 Success Prediction

For a selected DSA problem, CodeMentor estimates the probability that the student will successfully solve it.

Example:

```text
Problem: Binary Search

Estimated success probability
        63.4%

Moderate challenge — review the topic briefly, then try it.
```

The prediction is generated by a trained **Random Forest classifier**.

---

### 🧩 Weak Topic Detection

CodeMentor analyzes performance across DSA topics and identifies areas where a student may need more practice.

The weakness analysis considers both:

- success rate
- number of attempts

This prevents a topic with only one unsuccessful attempt from automatically being treated as the student's biggest weakness.

Example:

```text
Weak Area
Linked List

Attempts: 4
Successes: 1
Success Rate: 25%
```

---

### 🔁 Repeated-Failure Detection

Repeatedly failing the same problem is treated differently from simply exploring a new problem.

If a student repeatedly attempts a problem without solving it, CodeMentor can prioritize it in recommendations.

This creates recommendations such as:

```text
🔴 Critical
You have attempted this problem multiple times
without a successful solution.
```

---

### 🧭 Adaptive Recommendations

CodeMentor recommends problems using multiple signals rather than simply selecting random problems.

The recommendation engine considers:

- repeated failures
- topic weakness
- predicted success probability
- problem exploration
- historical success
- learning progression

It also supports **cold-start recommendations**.

That means a new student with no history can still receive useful problems instead of getting an empty recommendation list.

---

### 🌱 Cold-Start Learning Path

When a student has little or no practice history, CodeMentor starts with foundational DSA topics and gradually introduces more advanced areas.

For example:

```text
Arrays
   ↓
Searching
   ↓
Sorting
   ↓
Linked List
   ↓
Stack / Queue
   ↓
Recursion
   ↓
Trees
   ↓
Graphs
   ↓
Heap
```

As the student's history grows, recommendations become more personalized.

## 📊 ML Model

The project uses a **Random Forest Classifier** to predict whether a student is likely to successfully solve a DSA problem.

### Target

```text
1 → Successful submission
0 → Failed submission
```

### Features

The model uses behavioral features such as:

- previous number of attempts
- previous overall success rate
- recent success rate
- previous attempts on the current problem
- previous success rate on the current problem
- hour of practice
- day of the week
- days since the student's first submission

The current model deliberately avoids using the result of the submission being predicted as an input feature.

---

## 📈 Model Results

The final model was evaluated using a **chronological held-out test set**, rather than randomly mixing past and future submissions.

### Random Forest

| Metric | Score |
|---|---:|
| Accuracy | **64.2%** |
| Precision | **62.9%** |
| Recall | **67.6%** |
| F1 Score | **65.2%** |
| ROC-AUC | **0.696** |

The model is intended as a **learning-support signal**, not as a perfect predictor of whether a student will solve a problem.

The relatively strong recall for successful submissions makes the probability estimate useful as one component of the recommendation system.

---

## 🧠 How Recommendations Work

The recommendation engine combines several signals.

Conceptually:

```text
Recommendation Score
        │
        ├── Repeated Failure       45%
        ├── Topic Weakness         25%
        ├── Challenge Fit          15%
        ├── Exploration            10%
        └── Historical Difficulty   5%
```

A separate cold-start signal is used when the student has little or no history.

This creates three useful recommendation types:

### 🔴 Critical

Repeatedly attempted but not successfully solved.

### 🟠 High Priority

A problem belongs to an area where the student is struggling.

### 🟢 Explore

A problem introduces a topic or problem the student has not explored much yet.

## 🔄 How a Prediction Works

When a student selects a problem:

```text
Student
   │
   ▼
Select DSA Problem
   │
   ▼
Load Practice History
   │
   ▼
Build Behavioral Features
   │
   ▼
Random Forest Model
   │
   ▼
Success Probability
   │
   ▼
Personalized Feedback
```

For example:

```text
Previous attempts:              12
Previous success rate:          58%
Recent success rate:            60%
Problem attempts:                2
Problem success rate:            0%
```

The backend converts this history into the feature vector expected by the trained model and returns a probability.

---

## 🗄️ Data

The machine learning experiments use the **DSA Dataset – Zenodo**, containing historical programming submissions and DSA question information.

The dataset is used for:

- submission-level outcome prediction
- behavioral feature engineering
- problem/topic analysis
- recommendation development

The project does not use the student's current submission result as an input when predicting that same submission.

## ⚙️ Local Setup

### 1. Clone the repository

```bash
git clone https://github.com/NarmataGoel/CodeMentor-ML.git
cd CodeMentor-ML
```

### 2. Backend

Create and activate a Python environment:

```bash
conda create -n codementor python=3.11
conda activate codementor
```

Install dependencies:

```bash
cd backend
pip install -r requirements.txt
```

Create a `.env` file:

```env
MONGODB_URI=your_mongodb_connection_string
MONGODB_DATABASE=codementor
FRONTEND_URL=http://localhost:5173
```

Start FastAPI:

```bash
uvicorn app.main:app --reload
```

The API will run at:

```text
http://127.0.0.1:8000
```

API documentation:

```text
http://127.0.0.1:8000/docs
```

---

### 3. Frontend

Open another terminal:

```bash
cd frontend/leetcodeTracker
npm install
```

Create `.env`:

```env
VITE_API_BASE_URL=http://127.0.0.1:8000
```

Start the frontend:

```bash
npm run dev
```

The Vite development server will provide the frontend URL in the terminal.

## 🎓 What Makes This Project Interesting?

CodeMentor is not just a CRUD problem tracker.

It combines several layers:

```text
Student Behavior
       ↓
Feature Engineering
       ↓
Machine Learning
       ↓
Prediction
       ↓
Weakness Detection
       ↓
Recommendation
       ↓
Personalized Learning
```

The interesting part is the feedback loop:

> **The student's past behavior influences what the system recommends next.**

A learner who repeatedly struggles with linked lists should not receive the same recommendations as someone who has mastered linked lists but has never practiced graphs.

This turns a static DSA tracker into a small **adaptive learning system**.

## ⚠️ Limitations

The current model should be interpreted as a learning-support tool rather than a definitive measure of ability.

The training dataset and the application's student-history representation are different data sources, so the application reconstructs behavioral features that approximate the features used during model training.

The model is therefore best used to support recommendations and learning decisions rather than to make high-stakes judgments about a student's ability.
